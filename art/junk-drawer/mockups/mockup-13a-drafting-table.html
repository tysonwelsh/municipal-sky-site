Design notes — 13a · The Drafting Table

The move

  • Same manila form, turned sideways. One masthead spans two columns divided by a hairline gutter rule: left is the exhibit (the plate window with the MODEL / PROMPTED / PROCESS / SIZE fill-ins directly beneath it, like a figure caption); right is the paperwork (THE PROMPT, ANNOTATIONS, OTHER MODELS, download + accession footer). Nothing was added or removed from the content model — it is the shipped card re-laid.
  • The footer takes margin-top: auto in the right column, so “Download SVG” / “No.” sits level with the fill-ins across the gutter — the two columns close on one baseline like a ledger.
  • The twin teal grid is refined for the smaller window: stroke opacity 0.6 → 0.38 (rows) / 0.44 (rays), horizon GAP 44 → 30, glow band ±(GAP+62/2) → ±(GAP+20) with core opacity 0.32 → 0.22, line density S 112 → 120. Same geometry (geometric row recession, ROWK 0.62, 20 columns), same xMidYMid slice square viewBox — suggest a quiet flag on floorSVG() rather than a second function.

How the fit contract is met (the round-13 bug, fixed)

  • Scrim reserves the banner: .jd-record-scrim { inset: var(--banner-h) 0 0 0; } replaces inset: 0 (56px desktop, 48px mobile — read the token from css/style.css, don’t hardcode). The banner keeps its z-index 1000 and its stacking win; the card simply never enters its territory, so the masthead and the close ✕ cannot hide under it.
  • Card cap: the card is max-height: 100% of that reserved scrim, whose padding is max(12px, 2dvh) 14px — i.e. calc(100dvh − var(--banner-h) − 2×pad), border-box all the way down.
  • Plate height is vh-clamped, never width-derived: --plate: clamp(240px, min(52dvh, 42vw), 420px); the plate is a square of side --plate (the left grid column IS var(--plate) wide, the plate is width:100%; aspect-ratio:1/1). The shipped aspect-ratio:10/9-of-card-width plate — the ~465px tower that buried everything below it — is gone. The 42vw guard keeps two columns viable in the 700–1000px band.
  • The prompt folds, no always-on inner scrollbar: max-height: 7.4em; overflow-y:auto is deleted. Long prompts clip to max-height: 4.5em (3 lines × 1.5 line-height) with a mask-fade on the third line and a “SHOW FULL PROMPT” expander; short prompts render whole with no chrome at all. Expanded, the prompt joins normal flow — at target sizes the card still fits (demo 2b); only a pathological case would engage the card’s safety scroll.
  • Close always visible: the ✕ is absolutely positioned on the card (outside the scrolling box), and the card itself can no longer extend past the viewport or under the banner.
  • Zero internal scrolling, demonstrated: at 1280×800 and at 1280×680 the whole card — masthead to footer — is on screen with no scrollbar. .rc-body keeps overflow-y:auto purely as a safety valve for sub-500px-tall viewports (and for a user-expanded long prompt at those heights), and as the real scroll on phones.
  • The compact register: below ~600px of usable height the card gives up ~30px of air instead of growing a scrollbar — same form, set solid (tighter masthead, table cells, strip thumbnails, section gaps). In the mockup it is @container vp (max-height: 560px) on the frame; integration: @media (max-height: 660px) (frame height ≈ viewport − page header here).

Under 700px

  • The columns flatten to the portrait flow (masthead, plate, fills, prompt, annotations, strip, footer) via display: contents on the two column wrappers — DOM order already IS the portrait order, so no re-parenting in JS.
  • The plate stays vh-clamped (min(100%, 52dvh, 420px), centered), so a landscape phone cannot blow the card out vertically. The card body scrolls again — correct on a phone — and the close ✕ stays pinned.

Integration watch-outs

  • Mockup dialect: the demos are size containers standing in for the viewport, so this file says cqh/cqw and @container vp (max-width: 700px) where junk-drawer.css must say dvh/vw and @media (max-width: 700px). The existing 480px phone block folds into the new 700px block.
  • The expander needs JS in the real card: the checkbox here is mockup plumbing. cardHTML should render a <button aria-expanded> (only when the prompt overflows 3 lines — measure after render, or approximate by length > ~220 chars) toggling an .is-open class; same CSS otherwise. Reset the fold state when stepping through rc-alt responses re-renders the card.
  • Fold state vs. re-render: render() rebuilds the card's innerHTML on alt-switch; since the prompt is per-entry (not per-response), consider preserving the expanded state across that re-render.
  • The enlargement layer is untouched: .jd-record-zoom already lives on <body> at z 1100 and covers the banner deliberately; nothing here changes it. The plate keeps role="button" / tabindex="0" / the ⤢ hint.
  • artClass carries over unchanged (square-mass items get the tighter stage envelope; demo 1’s urn and demo 3’s crystal ball are the square case, demo 2’s magician the default).
  • Alt strip width: thumbnails keep flex: 1 1 0, so 2 responses widen (demo 3) and 4 (smashed-alarm-clock) narrow; at 4+ the labels are the constraint, not the art — unchanged from shipped behavior.
  • Grid column minimum: the right column is minmax(330px, 1fr); with the 42vw plate guard the two-column card holds down to the 700px breakpoint. If a future axis makes verdict words longer, widen the minimum before touching the breakpoint.
  • Version bump: shipping this is a user-facing junk-drawer change (not Prospero’s Jukebox); no VERSION file applies here, but the round-13 pick should land as one commit with the CSS + cardHTML changes together.
