Notes · what I committed to, what implementation must watch

1 · The premise. The double bench died because it judged two drawings at once; the single bench seats one. Each response gets the full instrument alone — overall grade, the five live axes, the report flag — and only the finale ever shows A and B together, because comparison is what that element is. The preserved Likert ships byte-for-byte: markup from likertHTML(), its CSS blocks, the pick state, the singleton tooltip, the ⓘ in-flow popover. It is mounted as the last step and wired through the same delegated handlers, nothing more. Everything renders from a JS const holding the taxonomy.json v10 subset verbatim — the five grades and the five live axes (defunct axes excluded), option values are the permanent rank numbers, exactly what production files.

2 · Dropdowns: native <select>, deliberately. The owner's goal is vertical compactness; a native select buys it with the best mobile behavior for free — the OS spinner/sheet on iOS and Android, full keyboard semantics (arrows, type-ahead, Esc), correct focus and screen-reader behavior with zero ARIA owed — where a custom listbox would make me own roving focus, aria-activedescendant, touch scrolling and every regression forever. The cost is that definitions cannot live inside options, and the standing rule wants titles-only options anyway, so nothing real was lost. The contract: option labels are level TITLES only (Prime … Utility; Followed / Drifted / Ignored; …), the closed control shows the chosen title only, skip is a real option and the default so an untouched scale is honestly "skip", a chosen value goes bold (.is-set — state never carried by color alone), and each select carries an aria-label naming scale + response ("Restraint for response A").

3 · One definition system, reused not duplicated. Every question row's head is the preserved .bench-def affordance: hover or keyboard-focus shows the preserved singleton tooltip with that scale's own definition; a press on the ⓘ unfolds the preserved .bench-pop in-flow with every level title + full definition (plus a "skip" line), pushing the sheet down rather than covering any control. The likert's stops keep their per-stop tooltips untouched. No second definition UI exists on the page.

4 · Sequencing: A → B → the call. A three-step rail sits in the sheet head: the current step carries aria-current="step", unreached steps are disabled so the first pass is honestly linear (next unlocks the following step), and every visited step stays a button — back is one press, on the rail or the ghost button in the step foot. The three panels are built ONCE and toggled with hidden — production's mutate-in-place discipline (the comment above ratePanel() is the precedent) — so answers survive navigation with no restore logic and hidden panels drop out of the tab order by construction. On a step change the scroll resets and focus moves to the step's heading (tabindex="-1"), which lives inside the sticky plate: the artwork being rated is pinned to the top of the scroll area, so the drawing stays in view for the entire panel, on the phone too. Notes collapse behind a per-axis ✎ affordance (never five empty inputs); the report flag reveals its note the same way, wording unchanged.

5 · The {winner, strength} contract — a proposed addition, flagged not invented. Production files comparison: {winner}; the preserved finale wants {"winner": "a"|"b"|"tie", "strength": "decisive"|"slight"} with strength OMITTED exactly when the winner is a tie. winner keeps its exact current meaning so the required-before-filing rule and existing rows are untouched; strength is one new optional field for jd-rate.php to accept. "File the grades" stays disabled until the call is made (both responses exist here); filing prints the one-batch payload — the same shape submitRatings() posts, mock ids standing in for gen_id/submission_id — into the office-use panel at the sheet's foot, live.

6 · What implementation must watch. (a) The one-survivor degraded turn: with a single ok slot the rail collapses to that response alone, the call panel never mounts, comparison: null stays legal and filing enables without a call — this page stages the two-slot flow only. (b) Notes and flag notes clamp to production's MAX_NOTE (500) and empty notes are omitted from the batch, as are skipped scales — never nulls. (c) The exhibits are minted from inert <script type="text/template"> sources with id=", url(# and href="# rewritten per copy (both real SVGs collide on glass-ids); production owns this via JD_svgInst. (d) Floors: nothing past iOS 16 — no popover attribute, no :has(), container queries as the salvage already used; sticky is plain position: sticky inside the existing scroll region. (e) Motion is decorative micro-transition only and killed under prefers-reduced-motion; the base state is static. (f) In production the sheet mounts inside the real turn modal, whose close/abandon path, focus trap and Escape layering are unchanged and out of scope here.

7 · The mobile pass (2026‑08‑11). A dedicated rework for a 375×667 baseline with a 320px floor, all of it inside a @container (max-width: 430px) block (plus a 340px floor block) so the desk presentation is untouched. What changed at phone width: the head goes on a budget — the long copy and the verbatim commission fold behind one ≥44px <details> tap (the copy is rendered twice, inline for desk and folded for phone, CSS shows exactly one; implementation may render once and restyle instead); the step rail compresses to three ≥44px chips labeled 1 · A / 2 · B / 3 · CALL, the current chip barred red on the lifted paper tone (never color alone); question rows wrap deliberately — label line (rowhead + ✎) above, a full-width ≥48px select below, so the whole row width is the tap target; the sticky plate slims to ~90px (art ≤78px, one-clause caption) so the drawing stays in view without taking half the screen; next/file go full width on top with back full width under them; every remaining target (ⓘ rowheads, ✎, flag row, note inputs, office summary) hits 44px. The touch definition contract: no hover exists on phones and the singleton tooltip is hover/focus-gated by design ((hover: hover)), so the ⓘ in-flow popover carries the full weight of every definition on touch — it is the one path, its type is bumped to phone-legible size in the narrow block, and it still pushes the sheet down rather than covering any control. Preserved-element narrow tuning, declared: (i) the shared .bench-def/.bench-i affordance grows to a 44px target with an 18px ring, and .bench-pop type is enlarged — additive overrides at ≤430px, base rules and behavior untouched; (ii) the likert itself needed exactly one floor tweak at ≤340px: cap tracking to zero, caps 0.47→0.45rem, gap 6→4px, because "decisively" kisses its ~45px column once the container drops under ~300px (a 320px phone yields ~270–300px depending on chrome) — geometry, order, stop heights and behavior unchanged, and nothing moves at 375px. What implementation must watch on real phones: the 16px control font rides a @media (max-width: 768px) viewport query (production's own .jd-turn-input rule) because container queries cannot see the device — verify no iOS focus-zoom on selects AND note inputs; scroll-padding-top on the scroll region keeps UA focus-scroll from parking a revealed note input under the sticky plate, but the on-screen keyboard interacts with the visual viewport in version-specific ways — test a note near the fold on real iOS; the real modal's ✕ occupies the head's top-right 44px, which the title margin still clears; and the OS select sheet is the picker — do not intercept it.
