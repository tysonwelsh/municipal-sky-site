NOTES · WHAT THIS COMMITS TO

The structural bet

One sheet, one pass. The two responses are pinned side by side (position: sticky against .jd-turn-scroll) and every question is one shared row: overall grade first, then the five live axes, each with A’s title-only chips on the left half and B’s on the right, on the same 3-column grid so the same level sits at the same coordinates on both sides — disagreement between the columns is visible at a glance. The comparison stops being a separate screen: after six rows of looking at both drawings, the 5-point call is the last row of the same bench, and one action files everything. Versus today’s instrument (two sequential report-card panels, then a compare screen) this halves the scrolling and never asks the visitor to grade from memory.

Definition mechanism, and its a11y contract

  • Chips and Likert stops are title-only. Hovering one (mouse/pen) or reaching its radio by keyboard shows a tooltip with that single level’s definition. A plain tap on a chip only ever selects — tooltips never open from touch, and the tooltip is pointer-events: none, so it can never take a press.
  • The row header is the touch affordance: the axis name + ⓘ is one button (aria-expanded/aria-controls) opening a popover with the axis description and every level’s definition. One mechanism serves both halves.
  • Popovers are in-flow, not overlays: they push the sheet down, cover nothing, and never block further rating. Dismissal: the button again, Esc (focus returns to the button), or a tap/click anywhere outside. One open at a time. Esc peels tooltip → popover before it ever reaches production’s abandon-confirm → modal layers.
  • Screen-reader parity is not the tooltip’s job: every radio carries aria-describedby to a static visually-hidden “Title — definition” node, so the definition is announced on focus regardless of pointer; the visual tooltip is aria-hidden. Radiogroup semantics are native (real radios, one name per side per axis, arrow keys move the tick, :focus-within ring on the chip). The keyboard-focus tooltip fires only when the input matches :focus-visible, so a mouse click doesn’t flash it.

The Likert, and the contract note

  • Five stops on one rail spanning the sheet — A anchored hard left, B hard right, matching the thumbnails above, so the geometry itself is the direction. Wording: A · decisively / A · narrowly / dead even / B · narrowly / B · decisively.
  • It files as comparison: { "winner": "a"|"b"|"tie", "strength": "decisive"|"slight" } — winner is unchanged from C1.3; strength is a contract ADDITION (absent for a tie). It needs a plan amendment and a column on jd_comparisons; this mockup does not invent the endpoint change, it flags it. Degraded one-survivor turns skip the call exactly as today (comparison: null).
  • As today, everything is optional except the call when both responses exist: file the grades stays disabled until a stop is picked. Skips file nothing (a skipped axis is an omitted entry, per the C1.3 ratings shape).

Mobile: the honest degradation

Two chip-columns cannot share 375px, so at container width ≤560px each row keeps its single shared header and becomes an A line above a B line (the side tags step up in weight; B’s line is set off by a dashed rule). The alternative — a segmented A/B toggle filtering one column — was rejected: it hides half the instrument, turns one pass per axis into two passes over the whole sheet, and quietly rebuilds the sequential panels this mockup exists to retire. The pinned pair (60px thumbs on phones) keeps both drawings in view either way. The rules are container queries on the sheet clamp (Safari 16+ — the drawer’s existing iOS 16 floor), which is also how stage 2 runs the phone layout on a desktop screen; production could ship the same rules as viewport media queries at ≤600px unchanged.

What implementation must watch

  • The sticky pin needs the sheet’s own paper + grain background and a z-index above the rows and popovers, or content ghosts through it; its grain tile won’t phase-match the sheet’s while scrolled — acceptable (it reads as a separate slip), but don’t “fix” it with background-attachment.
  • Inline SVGs must be id-namespaced per instance (JD_svgInst, as production already does) — this page mints four namespaced copies and their defs do not collide.
  • Flag notes live INSIDE the sticky strip so checking ⚑ while scrolled deep never reveals an input off-screen; like production’s flag note, reveal by toggling hidden in place — never re-render the rate state (focus + scroll position must survive).
  • Notes and flag notes keep MAX_NOTE (500); grade rows have no note (unchanged from production — notes are per-axis).
  • Base CSS is the reduced-motion state; transitions/keyframes exist only inside prefers-reduced-motion: no-preference.
  • The bench renders from the taxonomy payload (grades sorted by rank desc, axes filtered on !defunct) — nothing on this page is hardcoded that production wouldn’t read from data.php.
  • Tooltip positioning is viewport-fixed and hides on scroll; it must be appended to body, not the scroll container, or it clips.
