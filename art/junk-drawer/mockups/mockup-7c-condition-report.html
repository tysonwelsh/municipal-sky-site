Mockup 7c · The Condition Report — full record, style C

THE COSTUME. A page from a 19th-century sale catalogue. Cream laid paper (laid lines close-set, chain lines wide, plus a fibre wash), an engraved double hairline border, a fleuron at the head, and an old-style system serif — Iowan Old Style, then Palatino, then Georgia; no webfonts. Mono appears exactly once, in the quoted catalogue description, because on this page monospace means verbatim and nothing else. The eval rubric is recast as the art world’s own annotation form: the condition report, written in run-in sentence fragments — Geometry & topology: minor defects — small misalignments… — and closed by a classification line in letterspaced small caps. This is a PAGE, not a card, so it runs wider than its siblings and keeps generous margins.

Everything renders from the taxonomy. Grade labels and descriptions, the degree (“the third of five degrees”, from rank), axis labels in taxonomy order, value labels and value descriptions, model labels and vendors — all resolved from the baked taxonomy.json (schema 1, version 5). A condition fragment carries its value’s description only when that value is not the axis’s first (ideal) value, so “clean” stays clean and a defect explains itself; an annotation written as {value, note} prints the curator’s note in place of the taxonomy’s. Unknown axes and unknown value ids still render. Nothing in the page is hardcoded except the lot numbers (see below).

TWO SYNTHETIC OVERLAYS — disclosed here, never inside the page. The entries and the taxonomy are baked verbatim from items/; two states no real record carries yet are grafted on afterwards, in one clearly-marked block of JS, so the layouts can be judged: (1) subway rat r1 (Claude Opus 5) is given a grade_history entry {grade:"choice", date:"2026-07-27", note:"mock — for layout"}, which prints as the catalogue-corrigenda line “(Reclassified from Choice, 27 July 2026.)”; (2) subway rat r3 (Claude Sonnet 5) has its color annotation removed, so the skipped-axis fragment “Color & rendering: not assessed.” renders. Flip to the third hand to see it. The lot numbers (7 and 12) are the one other invention — in production the lot is the item’s position in the drawer; PLAN-RECORD §3 C permits the mockup to hardcode it.

Flip-through. The strip is captioned THE SAME SUBJECT, BY OTHER HANDS; choosing a hand swaps the lifted SVG inside the same fixed plate (same box, same scale) and re-renders only the per-response matter — the provenance line, the condition, the classification, the corrigenda, the footnote. The quoted description never changes: one prompt, every hand. The hairball has a single response, so the strip is absent entirely rather than empty. The four artworks share one document, so every id and url(#…) is prefixed per response (o_ f_ s_ h_), and clones for the plate and the strip are re-prefixed again at clone time.

Mobile. At ≤768px the page becomes the PLAN-MOBILE §4 bottom sheet: the lifted item holds the top 45svh, the sheet rests at peek (lot, title, provenance, classification, the strip) and rises to full (adds the quoted description, the condition, the footnote) with an inner scroll region. Tapping the handle toggles the detents; ?mock-state=peek and ?mock-state=full drive them for the verification screenshots.

Small calls to look at. Whether the provenance footnote (the clean-context / ink-bounds disclosure) still reads at phone size, or wants to be full-only even at peek. Whether THE DESCRIPTION, AS GIVEN above the quote earns its keep or the mono block should sit unlabelled, as a real catalogue would leave it. Whether CONDITION REPORT is the name (gate G7) or only the costume (gate G6).
