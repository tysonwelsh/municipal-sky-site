Design notes — 13c · The Microfiche Reader

The fiction, and what retired

  • The vaporwave floor (floorSVG, twin teal grids, navy sky) RETIRES. The artwork now sits in a municipal A/V reading machine: charcoal chrome (#23272e family), a dark glass window, and a warm light-table glow (#fff3d6 radial) behind the film. No perspective grid, no neon wireframe — the glow is the machine's lamp, CRT-era, not synthwave. Keep floorSVG in the source as a retired backup beside checkerFloorSVG (owner precedent, 2026-08-12).
  • The responses become mounted slides in a tray along the viewer's bottom edge — cardboard slide mounts (the brief's "slide-mount border" option), model printed on the mount, grade pencilled beside it in its earned colour (the mount is paper, so the spec colours rc-g1…g5 hold without a dark-theme variant). The current slide's window is backlit and its mount seats 1px deeper with the red current-border the old alt strip used.
  • MODEL / PROMPTED / PROCESS move onto the machine as a phosphor readout line under the tray — they describe the slide in the viewer and swap with it. SIZE stays on the paper (it belongs to the item), a single form fill under the masthead. The masthead itself moved below the machine: the machine is the card's face; the paper record begins with the title.
  • Visitor cards file BOTH drawings of a turn as slides; the kept one is the current slide and carries a hand-pen "✓ kept" on its mount. Curated items mount one slide per model response. A single-response item hides the tray entirely (same rule as today's altsHTML returning ''), and the viewer inherits the freed height automatically — it is the only flexible row.

How the fit contract is met (the point of round 13)

  • Scrim reserves the banner: .jd-record-scrim { position: fixed; inset: 0; top: var(--banner-h, 56px); } — the card can no longer slide under the banner, so the close ✕ (on the machine bezel, the card's top edge) is always visible. In this mockup the scrim is position:absolute only because it lives inside demo frames.
  • Card cap: the card keeps max-height: 100% with border-box sizing; because the scrim now starts at 56px and carries its own padding, that resolves to calc(100dvh − 56px − 2·12px) without any calc in the card itself.
  • The viewer is the one soft row: .mf-window { flex: 0 1 clamp(200px, calc(100dvh * 0.38), 430px); min-height: 150px; } (the mockup reads var(--vpH, 100dvh) so each demo frame can stand in for a viewport). Everything else in the column is flex: 0 0 auto, so when the viewport is short, flexbox compresses the viewer toward its 150px floor BEFORE the scroll container has anything to scroll. At 1280×680 the whole card — machine, paper, footer — fits with no internal scrollbar (demos 1–2a); at 1280×800 the viewer rides its ~38vh basis (~304px).
  • The prompt folds: .mf-quote.is-folded p { -webkit-line-clamp: 3 } replaces the old max-height: 7.4em; overflow-y: auto inner scroller (the nested-scroller bug). The expander button sits ON the section-head rule ("＋ show full prompt" / "− fold prompt") and is hidden by a scrollHeight check when the prompt fits in 3 lines. Unfolding may exceed the cap — the viewer gives its slack first, then the card's single thin scrollbar appears; that state is a deliberate reader action (demo 2b).
  • No other nested scrollers: the only overflow-y: auto left is the card's own .mf-scrollwrap; the tray scrolls on the x-axis only, on phones, when slides overflow.

Slide-swapping onto the existing data-resp mechanism

  • The tray buttons ARE the old .rc-alt buttons: same data-resp="i" attribute, same delegated click in build() — curResp = i; render(false). Nothing about the event wiring changes; altsHTML becomes trayHTML and moves from below the annotations up into the machine block that cardHTML emits.
  • Because render() already rebuilds the whole card per response, the readout line and annotations swap for free — this mockup's little JSON-driven swap script (~50 lines, bottom of file) exists only so the static page can demonstrate the interaction; it is NOT the integration plan.
  • Unlike the old strip (hidden under 2 responses), the tray should render for length ≥ 2 exactly as before; the counter in the bezel reads "SLIDE i / n" and doubles as the multi-response advertisement.
  • The enlargement reuses .jd-record-zoom (body child, z-index 1100 — already, and deliberately, above the banner): swap the floor for the light-table bed and optionally overlay the same tray markup at the right edge so data-resp keeps working while enlarged (Esc-peeling order unchanged).

Integration watch-outs

  • svgInst discipline stands: the viewer copy, the tray thumbnail, and the zoom copy of one response are three inlined copies of one SVG — each needs its own id prefix (jr/jt/jz) exactly as today. This mockup inlines each artwork once as a <symbol> and <use>s it, which the real card could adopt (one prefixed copy, three uses) to shrink the DOM.
  • dvh, not vh: the clamp and the cap use 100dvh so iOS URL-bar collapse doesn't open a gap or clip the footer. Fallback for old Safari: declare the vh line first, dvh second.
  • The machine needs an EXPLICIT min-height (285px = bezel + viewer floor + tray + readout). This was found the hard way in this mockup: with min-height: auto, Chromium computes the nested flex column's intrinsic minimum using the viewer's flex BASIS, so the outer flexbox never shrinks the machine at all and the card scrolls instead (the bug this round exists to kill). With min-height: 0 the bezel/tray/readout could be crushed. The explicit value replaces the automatic minimum and makes the shrink-to-floor behavior real — recompute it if the tray or readout metrics change.
  • Opaque-background art (e.g. the microscope slides) sits on the light table as a lit transparency — fine; but the bed's glow is invisible behind it, so the drop-shadow on .mf-art is what keeps it seated. Line art with transparent ground (most items) reads as backlit film — the flattering case.
  • Phone banner is 48px (--banner-h-mobile): the scrim must read the live banner var, not hardcode 56 — this file's phone view sets --banner-h: 48px the same way the site's media query does.
  • Verdict words stay per-response and re-render with the slide; "Has it" keeps its italic via the existing _it_ markdown in mark().
  • Grain/mottle: paper textures now apply to .mf-paper only — don't let the card-wide mottle overlay tint the machine chrome. All feTurbulence keeps stitchTiles="stitch" (standing Safari lesson).
  • This is a user-facing change to the record card — when it lands, remember the drawer's own changelog conventions (and the sibling rule precedent: bump any user-visible version marker in the same commit).

Inline script note: one small script at the foot of this file (a) swaps slides from the per-card JSON so the tray is clickable in the mockup, (b) runs the prompt expander, and (c) hides the expander when a prompt fits its 3-line fold. No external JS; everything else is CSS.
